# TaskTree 业务逻辑与系统架构说明

TaskTree 是 Nexus 系统中的另一个重磅核心模块，它旨在解决现代数字生活中日益碎片化的“待办与规划”问题。

如果说 ReadHub 负责“输入（Input / Info）”，那么 TaskTree 就负责“输出与执行（Output / Execution）”。它同样深度贯彻了 **Agent-Centric（大模型驱动）**的设计哲学。

---

## 1. 核心架构与模型设计

TaskTree 的数据底座采用了层级分明的**树状依赖结构**，与传统的单线 TODO 列表有本质区别。

### 1.1 数据实体关系
* **项目 (Project)**：宏观维度的容器，例如“国庆旅游计划”、“公司年度汇报”。具有总体状态（进行中、已归档）和最终截止日期。
* **任务 (Task)**：具体的执行单元。隶属于某一个具体的 Project。
  * **优先级 (Priority)**：高 (High)、中 (Medium)、低 (Low)。
  * **状态机 (Status)**：待处理 (Todo) ➔ 进行中 (In_Progress) ➔ 已完成 (Completed) ➔ 已取消 (Cancelled)。
* **评论与动态 (Comment/Activity)**：为 Task 提供上下文，记录用户或系统关于某个任务的讨论记录、附件链接以及状态流转历史。

### 1.2 ReadHub 与 TaskTree 的生态互通
在整个 Nexus 宇宙中，这两大模块是存在连通管的：
当用户在钉钉里读到一篇启发性的文章（来自 ReadHub），用户可以直接说：“把这篇文章作为一个灵感任务存到我的项目里”。系统后台会触发对应的逻辑引擎，将文章 URL 和摘要打包实例化为一个 Task，实现从“灵感输入”到“待办产出”的无缝转化。

---

## 2. 智能体 (Agent) 驱动下的任务生命周期

TaskTree 赋予了 AI 极高的自主权限，彻底颠覆了以往“用户需要打开 APP，一点点填写表单来创建任务”的繁琐流程。

### 2.1 规划与降维打击 (Plan Project)
当用户面临一个庞大且模糊的构想时（例如：“我下周要去日本东京玩 5 天，你帮我做个攻略并规划每天的行程”），TaskTree 并非只是死板地记下一句话。
* **AI 拆解规划**：大模型使用 `plan_project_tool.py`，根据海量的先验知识，将“日本游”这一抽象目标，自主拆分为“订机票酒店”、“整理签证材料”、“第一日行程：上野公园”、“第二日行程：秋叶原”等数十个颗粒度极细的具体 Task。
* **批量入库**：大模型在生成完详实的拆解树之后，会以事务操作批量将其写入 SQLite 数据库的 Project/Task 表中，甚至会给不同任务打上高、低不同的优先级。

### 2.2 多模态输入与创建 (Create Task)
用户可以通过钉钉语音、一段长文本的拷贝、或者随口的一句话下发任务。大模型利用强大的 NLU（自然语言理解）能力，会调用 `create_task_tool.py`，自动提取出任务的 Name、描述、隐式的 Deadline 和紧急程度，完成建档。

### 2.3 执行查询与进度追踪 (Query & Update)
* **查询能力**：通过 `query_task_tool.py`，大模型能够准确回答“我今天有哪些未完成的高优任务”、“下周那个项目的进展如何”等问题。
* **闭环更新**：用户口述“昨天说的那个 PPT 我已经写完了”，AI 将理解上下文意图，自动调用 `update_progress_tool.py`，将相关 Task 标记为已完成。

## 3. 异步回调与触达引擎 (Notification Engine)

一个优秀的目标管理系统必须具备出色的提醒和催办能力。

1. **多重提醒策略**：
   * **系统自动轮询**：底层通过 `apscheduler` 或消息队列周期性扫描即将逾期（Due Soon）的任务。
   * **Agent 自主苏醒**：未来架构将允许 AI 大脑自己预设 `schedule_task` 闹钟，主动醒来并审视任务进度。
2. **钉钉闭环提醒**：
   当触发提醒阈值时，`dingtalk_service.py` 的 `send_task_reminder` 接口会将任务被包装成具有极强视觉冲击力的 Markdown 消息卡片推送至用户的钉钉窗口。
3. **互动式催办 (Interactive Follow-up)**：
   推送到钉钉的卡片不仅仅是冷冰冰的提醒。卡片上往往附带 Action 链接。用户甚至可以直接回复钉钉卡片，从而触发 Agent 顺着这个上下文再次调用更新工具，完美实现 **“提醒 ➔ 对话 ➔ 更新状态”** 的全自动化极简闭环。
